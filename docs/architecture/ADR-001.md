# ADR-001: Fetcher value type

Status: Accepted

## Context

The robust-download try dispatch is a multi-path, multi-gate state machine (plain GET, Range resume, candidate fallback, 416). Binding that logic to `*Downloader` would force every unit test through a stubbed `api.Client`, progress UI, and rate limiter. Growing `downloadFile` in place would also couple orchestration to per-photo I/O.

## Decision

Per-photo download logic lives in a package-private `fetcher` **value type** in `fetch.go`. It owns the URL, final path, HTTP client, and injectable sleep/jitter/pre-try hooks. Fields are safe to copy; each `run` holds at most one in-memory fetcher so concurrent workers never share mutable fetcher state. `downloadFile` constructs a fetcher and delegates.

## Consequences

- Unit tests exercise BR5/AC paths without an `api.Client` or `Downloader`.
- `fetcher` has no dependency on `api.Client`, `ui.Progress`, or `rate.Limiter`.
- Rejected alternatives: in-place growth of `downloadFile`, full interface decomposition (`Transport`/`Validator`/`RetryPolicy`).
