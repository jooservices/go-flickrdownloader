# ADR-003: End-of-album stale-.part sweep

Status: Accepted

## Context

BR8/AC-017 require removing `.part`/`.cand` files whose photo ID is absent from this run's listing — but only inside fully-listed per-album directories. A startup sweep would need a second full album listing under the ~1 req/sec API limiter and separate dry-run gating.

## Decision

`sweepStaleParts` runs **after** `errgroup.Wait()` at the end of an album download, using IDs recorded at enqueue time. It runs only when the listing fully succeeded and the parent context was not cancelled. There is no startup sweep.

## Consequences

- Zero extra API cost; dry-run already skips download paths that call the sweep.
- A partial listing or Ctrl-C never deletes resumable artifacts.
- Orphan/owner-root batches never call the sweep (see ADR-007).
