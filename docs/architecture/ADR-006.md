# ADR-006: Read/write error split in copyCapped

Status: Accepted

## Context

`io.Copy` returns a single error for both network reads and filesystem writes. BR1/BR3 require network failures → INCOMPLETE (keep `.part`) and filesystem failures → FATAL (no retry that would thrash a full disk). AC-008 also needs a byte cap on gated 206 appends.

## Decision

`copyCapped` writes at most `limit` bytes (`limit < 0` = unlimited) and returns `(n, readErr, writeErr)` separately. Callers map read errors to INCOMPLETE and write errors to FATAL. A clean EOF is not an error.

## Consequences

- Disk-full and short-write cases fail fast without consuming further tries as if they were transient.
- Mid-stream network cuts leave a resumable `.part`.
- Cap and error classification happen in one pass.
