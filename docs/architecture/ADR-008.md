# ADR-008: Explicit 416 branch

Status: Accepted

## Context

HTTP 416 is a resume signal (AC-004/BR1), not an outcome. Folding it into `isFatalStatus` / `isRetryableStatus` / `classifyStatus` would invent a fake outcome at the one call site that must branch on `Content-Range: bytes */N`.

## Decision

416 is never classified by the status predicates. `rangeGet` handles it with an explicit branch: parse unsatisfied range; if `partSize == total`, validate and promote in place (no further request); otherwise fall back to plain-GET-into-candidate in the same try. Relatedly, `outcomeDone` is returned only after `promote` succeeds.

## Consequences

- AC-013 paths are one request (exact size match) or two (mismatch/unparseable).
- Predicates stay Boolean and free of special-case outcomes.
- A failed rename is never reported as success.
