# ADR-012: rangeGet failure classification

Status: Accepted

## Context

A Range request answered with 500, 429, or 404 says nothing about whether the existing `.part` is a valid continuation. Falling back to a candidate on every non-206 would spend a second request and risk discarding a good partial. Bodies not ingested must still be drained so connections return to the pool.

## Decision

`rangeGet` classifies transport and status failures identically to `plainGet` via `classifyTransport` / `classifyStatus`, with **no** candidate fallback on those paths. Candidate fallback is reserved for responses that are specifically unusable as continuations (Gate-A 206 identity failures, mismatched/unparseable 416). Every body not passed to `ingest` is `drainClose`d.

## Consequences

- Retryable Range failures preserve `.part` and consume a try like plain GET.
- FATAL 4xx on Range keeps `.part` and does not start a candidate rewrite.
- Connection reuse remains possible after rejected Range responses.
