# ADR-014: Read-error short-circuit

Status: Accepted

## Context

A short read or mid-stream failure (including the 60s client timeout mid-body) is INCOMPLETE by BR1. Running `validateFile` on a knowingly truncated file can produce UNUSABLE (size/sniff), which would delete the authoritative `.part` the next try must resume from.

## Decision

In `ingest`, a non-nil `readErr` from `copyCapped` short-circuits to INCOMPLETE immediately: no `validateFile`, no `promote`. An authoritative `.part` keeps already-written bytes; a `.cand` is discarded. Validation runs only after a clean copy and a clean `Close`.

## Consequences

- Timeout and mid-stream cuts leave a resumable `.part` (AC-003).
- UNUSABLE deletion cannot fire on a truncated resume base.
- Write/`Close` errors remain FATAL (ADR-006/ADR-009).
