# ADR-018: Match release archives by asset-derived binary name

Status: Accepted

## Context

`extractBinary` looked for a tar entry named exactly `flickrdownloader` (or `flickrdownloader.exe`) inside the downloaded archive. Every actually-published release (`v1.0.0` through `v1.2.0`, verified directly against the GitHub-hosted assets) packages the binary as `flickrdownloader_<goos>_<goarch>` — the same name as the archive itself, minus `.tar.gz`/`.zip` — not the bare binary name. `extractBinary` therefore never matched, and `flickrdownloader update` failed with "binary not found in archive" on every release to date; self-update has never worked in production.

## Decision

`extractBinary` now accepts a tar entry whose base name (after stripping an optional `.exe` suffix) is either the bare `BinName`, or `BinName_` as a prefix — covering both the actual `flickrdownloader_<goos>_<goarch>` layout every real release uses and the bare name, in case a future release changes packaging.

## Consequences

- Self-update actually functions for the first time as of this fix; verified by extracting a real `v1.2.0` release asset in a test.
- No release re-packaging is required — the fix matches the layout releases already use, rather than requiring releases to change to match the code.
