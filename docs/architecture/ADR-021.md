# ADR-021: Persistent photoset completion manifests

Status: Accepted

## Context

A user with many albums re-runs `download` expecting it to be fast: metadata is cached now, but every album is still fully re-listed page-by-page on every run, and each photo is re-resolved even when the album was verified complete last time. Listing every page of every album consumes most of the hourly budget even when nothing changed. Separately, there was no way to answer "is this album complete on disk?" without asking Flickr for its current listing.

## Decision

`pkg/cache` stores a **photoset completion manifest** per output root + owner + photoset:

- Once an album's pages have been fully listed and every expected file is present and size-validated, the manifest records the expected photo IDs, the output directory, the source `updated_at` timestamp, and per-photo file sizes.
- On later runs the downloader loads all manifests for an owner in one bulk query, indexes the local tree once, and **skips the listing request** for any photoset whose manifest matches: same directory, same expected count, same source timestamp, and all local files present at the recorded sizes. The album is rendered `✓ completed`.
- A manifest is invalidated by any mismatch (missing/short file, size change, directory move, or a changed source `updated_at`), and the album is re-listed.
- The same store powers a new `verify` command that reports completed / incomplete / not-scanned / stale photosets using disk + manifests only, with `--refresh` to rebuild expected-ID lists from Flickr.
- `--refresh` bypasses manifest reuse entirely; an uncategorized (owner-root) manifest is stored under a reserved `__uncategorized__` id so photostream scanning can also be skipped on re-runs.

## Consequences

- Re-runs of an unchanged account drop to nearly zero REST listing calls; verification of an already-downloaded account is possible with no network.
- Manifests describe local files, not remote state, so they survive re-authentication (see ADR-020) and are not pruned by cache expiry.
- Because manifests are only written after a fully-listed, fully-validated album, a torn or partial run never records a false "complete" — that is the invariant the skip path depends on.
- The completion check compares file sizes in addition to presence, so a truncated or zeroed file on disk is caught and repaired rather than silently skipped.
