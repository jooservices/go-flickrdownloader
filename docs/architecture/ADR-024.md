# ADR-024: Watchlist in the account cache database

Status: Accepted

## Context

Through 1.4.0 the watchlist lived in `~/.config/flickrdownloader/watchlist.yaml` (or `sources.txt`). That file was global to the machine, used a different format from the rest of the app, and `watch list` / `add` / `remove` never opened the SQLite cache already used for REST responses. Per-source options (albums, uncategorized, poll interval, output dir, workers) had no natural place to grow, and two Flickr accounts on one machine shared one list.

## Decision

1. **Store of record.** Watchlist rows live in the existing per-account cache database (`~/.config/flickrdownloader/cache-<hash>.db`, schema version 8). File-level globals (`poll_interval`, `output_dir`, `workers`) are keys in `cache_meta`. The watchlist is therefore **per Flickr account**.
2. **CLI default.** `watch`, `watch list`, `watch add`, and `watch remove` with no `--file` require `auth`, open the cache (hard-fail), and read/write the table. `cache clear` / `cache prune` do **not** delete watchlist rows or `watch.*` meta keys.
3. **`--file` hatch.** Passing `--file` keeps the YAML/text path used in 1.4.0. That format remains supported for people who want a file they can edit by hand.
4. **One-time import.** On the first DB-mode watch command, if `watchlist.yaml` or `sources.txt` exists, it is loaded, missing URLs are inserted, globals are copied, a `watch.legacy_imported` meta flag is set, and the file is renamed to `*.migrated` (not deleted).

## Consequences

- `watch add` / `list` / `remove` now require a saved OAuth config, matching `download`.
- Switching Flickr accounts switches watchlists with the cache file.
- A YAML file left beside the DB is imported once; later edits to `*.migrated` are ignored.
- Schema 8 is a forward-only migration of the same SQLite file documented in ADR-019.
